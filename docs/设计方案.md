## 1. 项目概述

### 1.1 目标
构建一个**私有文档问答系统**：用户上传自己的 PDF / Word / Markdown 等文档，通过对话方式提问，系统基于文档内容返回精确答案，并给出**来源溯源**（引用到具体文件和页码）。

### 1.2 用户场景
- 个人知识管理：论文、读书笔记、工作文档的快速问答
- 企业内部：规章制度、产品手册、技术文档的智能客服
- 未来扩展：通过企业微信在移动端随时问答

### 1.3 核心特性
| 特性 | 说明 |
|------|------|
| 多格式文档支持 | PDF、Word、Markdown、TXT、HTML |
| 语义问答 | 听懂同义词、换种说法、跨语言表达 |
| 流式回答 | 边生成边显示，体验丝滑 |
| 来源溯源 | 每个答案附带引用段落、文件名、页码 |
| 多知识库 | 可按项目/主题划分独立知识库 |
| 模型可切换 | LLM、Embedding 供应商可配置切换 |
| 企业微信接入 | v2 版本支持长连接机器人 |

### 1.4 非目标（本项目不做的事）
- ❌ 不做多模态（图片内容理解）——v3 可选
- ❌ 不做 Agent（自动工具调用）——v3 可选
- ❌ 不做公开对外 SaaS（仅内网/个人使用）
- ❌ 不做移动端 App（先 Web + 企业微信）

## 2. 核心名词速查表

> 这份表是整份文档的"词典"，看不懂的词回来查。

| 名词 | 英文 | 白话解释 |
|------|------|---------|
| **RAG** | Retrieval-Augmented Generation | 检索增强生成：AI 回答前先去你的文档里翻一下，再照着说 |
| **LLM** | Large Language Model | 大语言模型，如 DeepSeek / GPT-4 / 通义千问 |
| **Embedding** | — | 把一段文字变成一串数字（向量），代表文字的"语义坐标" |
| **Vector DB** | Vector Database | 向量数据库，专门存 Embedding 并快速找"坐标最近的 N 条" |
| **Chunk / Chunking** | — | 把长文档切成 300~500 字的小片段（便于检索） |
| **Retrieval** | — | 召回：从向量库找相似段落（粗筛，Top-20） |
| **Rerank** | — | 重排：用更精确的模型把粗筛结果重新打分（精筛，Top-5） |
| **BM25** | — | 传统关键词搜索算法（按字面匹配） |
| **Hybrid Search** | — | 向量搜索 + BM25 混合，结果更准 |
| **HyDE** | Hypothetical Document Embeddings | 让 LLM 先"假装回答"一次，拿假答案去检索，比原问题更准 |
| **Prompt** | — | 给大模型的指令文本 |
| **Prompt Template** | — | 带占位符的 Prompt 模板，运行时填入上下文和问题 |
| **Context Window** | — | 大模型一次能读的最大字数（DeepSeek-V3: 128K token） |
| **Token** | — | 大模型的计量单位，1 汉字 ≈ 1~2 token |
| **Streaming / SSE** | Server-Sent Events | 流式输出：服务器边生成边推给前端 |
| **Citation** | — | 溯源：回答里标明"来自 xx.pdf 第 3 页" |
| **FastAPI** | — | Python 现代 Web 框架（类似 ASP.NET Core） |
| **SQLAlchemy** | — | Python 的 ORM（类似 EF Core） |
| **Alembic** | — | Python 的数据库迁移工具（类似 EF Migrations） |
| **Pydantic** | — | 数据校验/序列化库（类似 DTO + FluentValidation） |
| **Celery** | — | 任务队列，跑后台耗时任务（类似 Hangfire） |
| **Redis** | — | 内存数据库，此处用作 Celery 的消息代理 |
| **Uvicorn** | — | ASGI 服务器（类似 Kestrel） |
| **uv** | — | 新一代 Python 包管理器（类似 NuGet） |
| **ASGI** | Asynchronous Server Gateway Interface | 异步 Python Web 网关协议 |
| **Collection** | — | Qdrant 里的"表"概念，一个 Collection 装一类向量 |
| **Point** | — | Qdrant 里的"行"，=(id, vector, payload) |
| **Payload** | — | Qdrant 的元数据字段，存原文、页码、文件名等 |

## 5. 数据流详解

### 5.1 文档入库流程

```
用户上传 foo.pdf
   │
   ▼
[1] FastAPI 接收文件（multipart/form-data）
   │   ├─ 校验：大小 ≤ 100MB、类型白名单
   │   ├─ 落盘：uploads/{knowledge_base_id}/{uuid}_{原名}.pdf
   │   └─ 写 DB：documents 表插入一条 (status=pending)
   ▼
[2] 返回 { document_id, status: "pending" }
   │
   ▼（同时）
[3] Celery 任务入队：process_document(document_id)
   │
   ▼（异步）
[4] Worker 取出任务
   │   ├─ 读文件 → pypdf 抽取文字 + 页码
   │   ├─ 分块（见 7.2）：default 512 char + 50 char overlap
   │   ├─ 批量调用 Embedding（阿里云 API 或本地 bge-m3）
   │   ├─ 批量写入 Qdrant：(vector, payload={text, page, doc_id, kb_id, chunk_idx})
   │   └─ 更新 DB：status=ready, chunk_count=N
   │
   ▼
[5] 前端通过轮询或 SSE 感知状态变化
```

### 5.2 问答流程

```
用户提问："我的请假制度是什么？"
   │
   ▼
[1] POST /api/chat/stream（SSE 长连接）
   │
   ▼
[2] GenerationService.ask()
   │
   ├─ [2.1] （可选）HyDE：LLM 先生成假答案 →
   │        查询向量 = Embedding(假答案)
   │        否则 查询向量 = Embedding(原问题)
   │
   ├─ [2.2] RetrievalService.retrieve()
   │        ├─ Qdrant 检索 Top-20（with kb_id 过滤）
   │        ├─ （可选）BM25 检索 Top-20 并合并
   │        └─ Reranker 对候选打分 → Top-5
   │
   ├─ [2.3] 拼 Prompt（见第 12 章模板）
   │        ├─ 系统指令：你是助手，只能根据资料作答
   │        ├─ 上下文：Top-5 段落（含来源标记）
   │        └─ 用户问题
   │
   ├─ [2.4] LLMAdapter.stream_chat()
   │        ├─ 调 DeepSeek/OpenAI/通义 流式接口
   │        └─ yield 每个 token 到 FastAPI SSE 通道
   │
   └─ [2.5] 流式结束后
            ├─ CitationService.extract() 从 Top-5 提取溯源元信息
            ├─ 写会话历史到 DB
            └─ 最后一帧 SSE 带完整 citation 列表

前端：
   ├─ 边收边渲染答案
   └─ 收到 citation 帧后渲染"来源卡片"
```

### 7.2 分块策略

**实现**：使用 LlamaIndex 的 `SentenceSplitter`（仅此一处用到 LlamaIndex），针对中文做了分隔符定制。

- 块大小：512 字符（可配置 `CHUNK_SIZE`）
- 块重叠：50 字符（可配置 `CHUNK_OVERLAP`）
- 段落分隔：`\n\n`
- 二级分块正则：`[^,.;。？！；，]+[,.;。？！；，]?`（中英文标点均识别）

**元信息保留**：每块携带原文、所在文件、页码（PDF）或章节（Markdown）、全局 `chunk_idx`、段内 `sub_chunk_idx`。

**各格式处理**：
- PDF：pypdf 提取文字，metadata 保留页码
- DOCX：python-docx 按段落提取，metadata 保留段落编号
- Markdown / TXT / HTML：直接提取纯文本后统一走 SentenceSplitter
- 长段落（>512 字符）由 SentenceSplitter 自动切分

### 7.3 文件解析器抽象

```python
class BaseParser(ABC):
    @abstractmethod
    async def parse(self, file_path: Path) -> list[ParsedSegment]:
        """返回 [(text, metadata), ...]"""

class PdfParser(BaseParser): ...
class DocxParser(BaseParser): ...
class MarkdownParser(BaseParser): ...
class HtmlParser(BaseParser): ...
```

`ParsedSegment` 结构：
```python

    text: str
    metadata: dict[str, Any]  # {"page": 3, "section": "第2章", ...}
```

## 10. 向量库 Collection 设计

### 10.1 Collection 命名
```
kb_{knowledge_base_id}     # 每个知识库一个 Collection
```

**为什么一个 KB 一个 Collection**：
- 检索时直接按 KB 隔离，不需要过滤（更快）
- 删除 KB 时直接删 Collection（O(1)）
- 不同 KB 可用不同 Embedding 模型/维度（灵活）

### 10.2 Point 结构
```python
{
    "id": "<uuid>",
    "vector": [0.012, -0.034, ...],  # 1024 维（bge-m3）或 1536 维（OpenAI）
    "payload": {
        "doc_id": 1,
        "kb_id": 1,
        "chunk_idx": 3,
        "text": "员工每年可享有 15 天带薪年休假...",
        "metadata": {
            "filename": "员工手册.pdf",
            "page": 12,
            "section": "第三章 · 休假"
        }
    }
}
```

### 10.3 索引配置
- 距离度量：**Cosine**（适合嵌入向量）
- HNSW 索引：默认参数 `m=16, ef_construct=100`
- payload 索引：`doc_id`（精确删除用）、`kb_id`（如共享 Collection）

## 11. Embedding 双通道设计（关键）

### 11.1 设计目标
- 阿里云 API 和本地 bge-m3 **两个口都能用**
- 通过配置 `EMBEDDING_PROVIDER=dashscope|local_bge` 切换
- 代码其他部分**无感知**

### 11.2 抽象接口
```python
# app/rag/embedders/base.py
from abc import ABC, abstractmethod

class BaseEmbedder(ABC):
    name: str
    dimension: int

    @abstractmethod
    async def embed_texts(self, texts: list[str]) -> list[list[float]]:
        """批量文本 → 向量"""

    @abstractmethod
    async def embed_query(self, query: str) -> list[float]:
        """单个查询 → 向量（有些模型查询/文档有前缀差异）"""
```

### 11.3 阿里云 DashScope 实现
```python
# app/rag/embedders/dashscope_embedder.py
class DashScopeEmbedder(BaseEmbedder):
    name = "dashscope:text-embedding-v3"
    dimension = 1024

    def __init__(self, api_key: str):
        self._api_key = api_key

    async def embed_texts(self, texts: list[str]) -> list[list[float]]:
        # 批量 API（每批最多 25 条）
        results = []
        for batch in chunked(texts, 25):
            resp = await dashscope.TextEmbedding.acall(
                model="text-embedding-v3",
                input=batch,
                api_key=self._api_key,
            )
            results.extend([item.embedding for item in resp.output.embeddings])
        return results
```

### 11.4 本地 bge-m3 实现
```python
# app/rag/embedders/local_bge_embedder.py
class LocalBgeEmbedder(BaseEmbedder):
    name = "local:bge-m3"
    dimension = 1024

    def __init__(self, model_path: str = "BAAI/bge-m3"):
        from FlagEmbedding import BGEM3FlagModel
        self._model = BGEM3FlagModel(model_path, use_fp16=True)

    async def embed_texts(self, texts: list[str]) -> list[list[float]]:
        # 本地 GPU/CPU 推理（包裹在 asyncio.to_thread 避免阻塞）
        import asyncio
        result = await asyncio.to_thread(
            self._model.encode, texts, batch_size=32, max_length=512
        )
        return result["dense_vecs"].tolist()
```

### 11.5 工厂选择
```python
# app/rag/embedders/factory.py
def get_embedder() -> BaseEmbedder:
    from app.core.config import settings
    if settings.EMBEDDING_PROVIDER == "dashscope":
        return DashScopeEmbedder(api_key=settings.DASHSCOPE_API_KEY)
    elif settings.EMBEDDING_PROVIDER == "local_bge":
        return LocalBgeEmbedder(model_path=settings.LOCAL_BGE_MODEL_PATH)
    else:
        raise ValueError(f"Unknown provider: {settings.EMBEDDING_PROVIDER}")
```

### 11.6 重要约束：**一个知识库一次建库只能用一个 Embedding 模型**
- 如果中途切换，向量空间不一致会全乱
- 解决：KB 表里记录 `embedding_model` 字段，切换时提示"该 KB 已绑定 xx 模型，如需切换请重建"

## 15. 企业微信集成（v2）

### 15.1 接入模式
使用企业微信 **智能机器人长连接模式**（2026-03 官方推出）。优点：
- **无需公网域名**
- **无需 SSL 证书**
- 本地/内网服务可直接连

### 15.2 流程
```
本地 Python 服务
   │ 使用 BotID + Secret 建立 WebSocket 连接
   ▼
企业微信服务端
   │ 用户在企微对话框 @机器人
   ▼
推送消息到 WS
   │
   ▼
Python 收到消息 → 调 /api/chat/stream → 拼装回复 → 通过 WS 发回
```

### 15.3 实现骨架
```python
# app/wecom/bot.py
class WeComBot:
    async def run(self):
        async with websockets.connect(self._ws_url, extra_headers=self._auth_headers) as ws:
            async for message in ws:
                await self._handle(ws, json.loads(message))

    async def _handle(self, ws, msg):
        user_question = msg["content"]
        # 调用本地 RAG
        answer = await self.rag_service.answer(user_question, kb_id=self.default_kb)
        await ws.send(json.dumps({
            "type": "reply",
            "msg_id": msg["msg_id"],
            "content": answer,
        }))
```

## 19. 风险与取舍

| 风险 | 影响 | 应对 |
|------|------|------|
| Windows 上 Celery 并发有限 | 开发期 OK，生产慢 | 用 `-P solo` 或 `eventlet`；上线用 Linux |
| 本地 bge-m3 首次下载 ~2GB | 首次慢 | 提示用户，或默认用 DashScope API |
| 大 PDF（>100MB）解析慢/OOM | 体验差 | MVP 限制 100MB，超大文件 v2 引入 MinerU + 流式处理 |
| 中文分块导致语义割裂 | 召回变差 | 默认保留 overlap + 优先按标点切 |
| Token 超限（128K） | 生成失败 | 上下文管理：Top-5 片段 + 历史消息裁剪 |
| DeepSeek 偶发不稳 | 问答失败 | Adapter 层加重试 + 可切换到备用 LLM |
| Qdrant 内嵌模式不支持并发写 | 多 worker 冲突 | MVP 用 `-P solo` 单进程；切 Qdrant server 后解决 |
| Embedding 模型切换污染数据 | 检索混乱 | KB 记录 `embedding_model`，切换前提示 |
